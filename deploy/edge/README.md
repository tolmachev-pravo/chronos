# Общий входной прокси сервера

Один nginx на Docker-хост. Он держит порт 443 и по имени хоста отдаёт каждый запрос нужному
приложению. Chronos подключается к нему как одно из приложений. Любое другое приложение на этом же
сервере подключается так же: один файл сайта и сеть `edge`. Общие файлы здесь при этом не меняются.

## Схема

```
браузер ──HTTPS──> балансировщик (публичный сертификат *.example.com)
                         │ HTTPS на <сервер>:443
                         ▼
                   edge-nginx ──HTTP──> chronos:8080
                         │      ──HTTP──> другое-приложение:порт
```

Если публичный TLS завершает внешний балансировщик, который ходит на сервер тоже по HTTPS, но
сертификат бэкенда не проверяет, nginx отвечает ему самоподписанным сертификатом из `make-cert.sh`.
Когда DNS-запись вида `*.example.com` указывает на балансировщик, для нового приложения DNS и
сертификат трогать не нужно.

## Что где лежит

| Путь | Что | Кто меняет |
| --- | --- | --- |
| `docker-compose.yml` | контейнер `edge-nginx` на 443 | никто, общий |
| `conf.d/edge.conf` | TLS, реальный IP клиента, WebSocket, resolver Docker, 404 для чужих хостов | никто, общий |
| `snippets/proxy.conf` | заголовки прокси, подключаются в каждом сайте | никто, общий |
| `sites/<приложение>.conf` | один файл на приложение: хост → контейнер | владелец приложения |
| `certs/` | сертификат для 443, делает `make-cert.sh`, в git не попадает | один раз |

## Установка, один раз на сервер

Скопируйте эту папку на сервер, например в `~/edge`, и выполните в ней:

```bash
docker network create edge
```
```bash
./make-cert.sh
```
```bash
docker compose up -d
```

## Как подключить приложение

1. **Контейнер в сети `edge`.** В compose приложения:

   ```yaml
   services:
     myapp:
       container_name: myapp        # по этому имени nginx его найдёт
       networks: [ default, edge ]

   networks:
     edge:
       external: true
   ```

   Порт приложения наружу публиковать (`ports:`) не нужно: nginx ходит к нему через сеть `edge`.
   Имя контейнера должно быть уникальным на сервере.

2. **Файл сайта.** Скопируйте `sites/example.conf.sample` в `sites/myapp.conf` и впишите хост и
   контейнер с портом:

   ```nginx
   server {
       listen 443 ssl;
       server_name myapp.example.com;

       location / {
           set $upstream http://myapp:8080;
           proxy_pass $upstream;
           include /etc/nginx/snippets/proxy.conf;
       }
   }
   ```

3. **Перезагрузите nginx.** Проверка конфигурации идёт первой, поэтому ошибка в новом файле не
   уронит работающие сайты:

   ```bash
   docker exec edge-nginx nginx -t && docker exec edge-nginx nginx -s reload
   ```

Чтобы убрать приложение, удалите его файл из `sites/` и перезагрузите nginx так же.

Контейнер в файле сайта задан через переменную (`set $upstream`). Поэтому nginx ищет его при каждом
запросе, а не один раз при старте. Остановленное приложение даёт `502` только на своём хосте, а nginx
и остальные сайты продолжают работать.

Для Chronos всё уже готово: сеть подключается файлом `docker-compose.edge.yml`, а файл сайта —
`chronos.edge.conf` (см. [deploy/docker/README.md](../docker/README.md)).

## Проверка

- Прямо с сервера, минуя балансировщик:
  `curl -sk https://127.0.0.1/ -H "Host: myapp.example.com"`.
- Хост, для которого нет файла сайта, получает `404`.
- Логи доступа и ошибок: `docker logs edge-nginx`.
