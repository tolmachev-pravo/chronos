Chronos теперь можно развернуть на Linux-сервере в контейнере Docker. Каждый релиз публикует
готовый образ, поэтому собирать приложение на сервере не нужно: достаточно указать версию и
запустить. Развёртывание на Windows и IIS работает как раньше, оба варианта могут жить
параллельно.

![Как Chronos работает в Docker](/documents/features/docker-deployment/images/docker-deployment.svg)

## Что это даёт

- **Не нужен Windows-сервер.** Chronos запускается на любом Linux-сервере с Docker.
- **Одинаковая сборка везде.** В образе та же протестированная версия, что и в архиве релиза для IIS.
- **Простое обновление и откат.** Версия задаётся одной строкой, а откат — это запуск предыдущей версии.
- **Данные в одном месте.** База, ключи шифрования и логи лежат в одном томе `/data`, поэтому
  пересоздание контейнера ничего не теряет, а бэкап делается одним архивом.
- **Несколько приложений на одном сервере.** Общий входной nginx по имени хоста отдаёт
  запросы нужному приложению. Новое приложение подключается одним файлом сайта.

## Как развернуть

1. Установите на сервер Docker и Docker Compose.
2. Скопируйте файлы из папки `deploy/docker` репозитория и укажите в `.env` нужную версию.
3. Выполните `docker compose pull && docker compose up -d`.

Подробная инструкция с настройкой прокси, автодеплоем, бэкапом и переносом данных с IIS лежит в
`deploy/docker/README.md`, а про общий nginx — в `deploy/edge/README.md`.

> 💡 Если с сервера недоступен публичный адрес Jira, задайте внутренний в настройке
> `Jira:ApiUrl`. Сервер будет ходить в Jira по нему, а ссылки на задачи и профиль, которые вы
> видите в интерфейсе, останутся на привычном адресе.

> ⚠️ Переносите базу и папку ключей DataProtection только вместе. Ключи шифруют пароли и
> токены, сохранённые в расширениях, и без них эти секреты не расшифровать.
